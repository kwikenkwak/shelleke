Paper A — “Hairline” · tokens

The most minimal of the three paper variants. Warm off-white ground, near-black ink, one hairline weight as the only structural device. No filled panels, no boxes, no shadows, no texture, no radius. Ink is never used as a background larger than 6 px — that ceiling is what makes the whole system hold together.

Type: the shell sets body/UI in Inter (google-inter-fonts / ttf-inter) and every numeral, identifier and path in JetBrains Mono (already installed here). These pages fall back to Adwaita Sans — an Inter derivative — when Inter is absent, so shapes are within a hair of the real thing; all sizes, weights, tracking, colours and metrics are the real values.

Accent policy

There is exactly one hue in the system and it is spent on almost nothing. alert is permitted on: battery ≤ 15 %, a failed daemon or script operation, an urgent notification’s 6 px dot, the “package manager is running” session warning, and a field that failed validation. It is never used for “on”, “active”, “selected”, “connected”, “focused” or “playing” — those are ink weight and rules. Album art is the only place third-party colour is allowed through, exactly as in the pixel theme.

Type scale

Two families. Inter for language, JetBrains Mono for anything the eye has to compare or a machine produced: clocks, percentages, resolutions, coordinates, paths, bookmarks, log output, workspace numbers, keyboard accelerators. Chosen over IBM Plex Sans because Inter’s x-height survives 10–11 px hinting on Wayland, and over a display serif because Hairline gets no display face at all — titles are body type in micro-caps, which is the cheapest possible way to signal hierarchy. One optical rule: as size goes up, weight comes down (≤11 px → 500, 12–18 px → 400, 24 px → 300, 40 px → 200).

Rule weights — the entire structural vocabulary
hairDefault. Panel border, list separators, section dividers, calendar grid
hair-halfDense lists and the calendar. 0.5 device px on 2× outputs, 1 px @ 55 % on 1×
hair-findA hairline the user must be able to aim at: field underlines, switch rail, hover
hair-inkThe selected / active / focused marker. Nothing else in the system is ink-weight
hair-alertFailed validation on a field. The only coloured rule

There is no 2 px rule, no 3 px rule and no border radius anywhere in the system. Corners are square; the only curves are icon strokes and the 6 px state dots.

Icon grid

16 × 16 viewBox, live area inset 1 u, key strokes on the half-unit grid. Round caps, round joins, no fills except a 1.9 u dot where a glyph genuinely terminates in a point (Wi-Fi, regex, list bullets). Apparent stroke is a constant 1.25 px at every optical size — the SVG stroke-width is 20 / size, so a 28 px session glyph is drawn with the same pen as a 12 px row glyph and reads as a fine engraving rather than a heavy pictogram.

Third-party app icons

Where a mapping exists (terminal, browser, editor, chat, files, image viewer, music) the shell substitutes its own line glyph. Everything else is the real .desktop icon desaturated and multiplied to ink-2 at 14–16 px — one ink, no third-party colour, same as the pixel theme’s greyscale rule. Unresolvable icons fall back to puzzle (message inside notifications).
